---
description: Validate, render and check both pipeline layers, run the Node tests, and report what is stale, erroring or unconfirmed.
argument-hint: "[trip-id|--all]"
allowed-tools: Bash(node:*), Bash(git status:*), Bash(git diff:*), Read, Grep, Glob
---

Run the full check across both layers for `$ARGUMENTS` (empty means every case and
every trip). Run these in order and do not stop at the first non-zero exit — collect
everything, then report once.

```
node pipeline/cli.cjs list
node pipeline/cli.cjs validate --all
node pipeline/cli.cjs check --all
node pipeline/trip/cli.cjs list
node pipeline/trip/cli.cjs renderers
node pipeline/trip/cli.cjs validate $ARGUMENTS
node pipeline/trip/cli.cjs check $ARGUMENTS
node --test tests/pipeline.test.cjs tests/trip_foundation.test.cjs
```

If `check` reports a stale output, re-render that layer and check again:

```
node pipeline/cli.cjs render --all
node pipeline/trip/cli.cjs render $ARGUMENTS
```

then `git status --short` and `git diff --stat` so the regenerated bytes are visible
rather than silently committed.

Report, in this order and briefly:

1. **Errors**, layer by layer, each with the check name and the id it names. Errors
   block rendering, so nothing downstream is trustworthy until they are gone.
2. **Stale outputs**, if any remained after re-rendering — that means a renderer is
   non-deterministic (a clock, a random value, an absolute path) and it is a bug in
   the renderer, not in the record.
   **If the trip layer reports `outputs current (0 file(s))`, no renderer is installed
   and nothing was compared.** Report it that way. A check that examined zero files
   passes for the same reason an empty test suite does, and calling it a pass is how
   an unverified document in `pipeline/trip/out/` gets treated as current.
3. **Warnings, grouped, not listed one by one.** Most will be
   `days.slots … Not confirmed: <client word>`, which is the system working: an
   unconfirmed line is supposed to say so. Say how many and which suppliers.
4. **Test results**, pass/fail counts.
5. **One next action.** Not a list.

Do not edit any record to make a check pass, and do not commit. If a warning looks
wrong, say why; a warning that is cleared without being understood is how a
`sourcing` line ends up printed as booked.
